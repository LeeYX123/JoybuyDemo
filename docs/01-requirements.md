# 产品与需求规格

## 1. 项目目标

建立一个桌面端和移动端均可使用的 Joybuy 网页复刻系统，包含：

- 购物端：以公开可达的 Joybuy 网站为视觉和交互基线；
- 平台管理端：管理爬虫、目录、商品、媒体、评价、买家、内容和待支付订单；
- 商家领域模型：首期保留账号、商家、权限、商品归属和订单归属基础能力；
- 商家端 UI 与业务：等待用户提供参考网页后另行立项，不在首期臆测实现；
- 数据采集：按类目或全站抓取真实公开商品、评价和媒体，支持增量更新；
- 部署：前期本地开发，功能验收后部署到单台 Ubuntu 服务器。

## 2. 技术边界

- 后端：Python、Django、Django REST Framework；不采用 Flask。
- 购物端：Nuxt 3（Vue 3、JavaScript、SSR 用于首屏渲染；不建设 SEO）。
- 平台管理端：Vue 3 + Vite + JavaScript。
- 商家端：技术基座预留 Vue 3 + Vite，页面和功能待定。
- 数据库：MySQL。
- 异步任务：Celery + Redis。
- 爬虫：Scrapy + Playwright 混合模式。
- 入口与静态资源：Nginx。
- 搜索：MySQL 搜索表、FULLTEXT 和组合索引；不使用 OpenSearch。
- 所有字体、图标、图片、视频和构建产物本地托管，不引用任何 CDN。

## 3. 首期购物端范围

### 3.1 必须可用

- 首页、导航、分类、搜索、筛选和排序；
- 活动、专题、帮助、博客和其他公开内容页面的复刻；
- 商品列表、商品详情、SPU/SKU 选择、价格和活动标签；
- 来源评价展示、评价图片/视频、评分分布；
- 邮箱和手机号注册/登录、验证码和基础账户中心；
- 收藏、最近浏览、购物车、匿名购物车与登录后购物车合并；
- 英国地址、邮编、配送/自提、运费计算和结算页；
- 提交结算时创建正式待支付订单；
- 点击支付时提示“当前地区暂不支持”；
- 待支付订单在 60 分钟后自动取消并释放库存；
- 待支付与已取消订单在买家端和平台端可查询；
- 订单、账户安全等系统通知的站内信、邮件和短信模板能力。

### 3.2 展示为主

- 来源价格、划线价、折扣、促销标签和推荐位；
- JoyPlus、积分、优惠券、礼品卡及复杂促销页面；
- App 专属功能的网页提示、二维码或占位入口；
- 预售、Repeat & Save 等支付相关功能的页面和数据结构。

首期购物车按当前有效售价计算，但不执行复杂优惠叠加、会员权益、积分抵扣、礼品卡抵扣或周期扣款。

### 3.3 明确不做

- 真实支付、成功支付订单、真实退款；
- 发货、物流、签收、退换货和售后执行界面；
- 原生 iOS/Android App；
- 自建在线客服或工单系统；仅预留第三方客服入口与适配接口；
- SEO、公开 sitemap 和搜索引擎优化；所有页面默认 `noindex, nofollow`；
- 访问门禁；站点可通过网址公开访问；
- OpenSearch；
- 经营分析、用户行为分析和推荐模型；
- 买家数据导出、真实账户注销和完整隐私中心；账号只支持停用；
- Facebook、Google 和 Apple 登录。Facebook、Google 计划第二阶段接入，Apple 远期评估；
- 商家端具体页面与完整业务流程。

## 4. 平台管理端首期范围

- 买家账号查看、启停和基础状态管理；
- 员工账号、平台角色和权限；
- 商家、员工与 `MerchantMembership` 基础管理；
- 来源类目树、本地类目树和映射；
- 品牌、SPU、SKU、Offer、价格、库存和来源字段管理；
- 来源值与本地覆盖值的差异、审核和回滚；
- 媒体、评价、虚拟评价用户和数据质量管理；
- CMS：横幅、楼层、商品池、活动页、预览、定时发布和回滚；
- 爬虫账号会话、任务、进度、失败、风控暂停和数据质量告警；
- 待支付/已取消订单查看和筛选；
- 邮件、短信、站内信模板；
- 系统配置、审计日志、监控入口和备份状态。

## 5. 账户与权限

- 买家使用独立 `BuyerAccount` 表和认证端点；
- 商家员工与平台人员共用 `StaffAccount`；
- 买家与员工使用不同 Cookie 名称和权限命名空间；
- `StaffAccount` 可通过 `MerchantMembership` 加入多个店铺，并在每个店铺拥有不同角色；
- 平台角色为全局角色；
- 平台管理员强制 TOTP；商家可配置是否强制员工 TOTP；
- 浏览器认证使用 Secure、HttpOnly Cookie 会话，不把 JWT 放入 localStorage；
- 关键后台操作记录操作者、租户、IP、请求 ID、变更前后值和原因。

## 6. 商品、库存与订单原则

- 商品模型：`SPU -> SKU -> Offer`；
- Offer 归属商家；来源卖家映射为本地虚拟商家，缺失时归入“Joybuy 自营导入”；
- 抓取商品默认本地库存为 `9999`，前台显示 `999+`；
- 确认结算时事务性预占库存并创建 `PENDING_PAYMENT` 订单；
- 支付入口只返回地区不支持，不产生成功支付；
- 60 分钟超时后订单变为 `CANCELED` 并释放库存；
- 底层预留统一订单、商家履约子单和包裹结构，但首期不执行履约；
- 所有库存变化写入库存流水，不允许仅修改一个无审计的数量字段。

## 7. 数据真实性

- 不伪造来源销量、排名、评价或库存事实；
- 来源没有公开的字段保持为空；推导数据必须标记为估算；
- 来源字段与本地演示字段分开保存；
- 来源值与本地覆盖值分层，爬虫不得覆盖人工审核后的本地值；
- 来源评价和本站真实评价明确标识；本站评价能力保留，但只有已完成订单才能评价，首期因无成功订单不会产生本站评价；
- 来源评价修改或删除时保留版本和软删除痕迹，前台不展示已删除内容。

## 8. 国际化

- 原首期基线为 `en-GB`、`GBP`、`Europe/London`；2026-11-03 起扩展为多市场、多语言设计，详细方案见 [多语言商品内容与国家市场设计](./10-multilingual-content-and-market-design.md)；
- Joybuy 来源分析优先使用简体中文页面，抓取文本必须显式记录 `source_locale`；
- 商品标题、卖点、详情、类目、属性和活动文案按 `market + requested_locale` 保存 Joybuy 实际返回的版本；德国页面实际德英混合时必须原样复刻；
- 国家市场与展示语言分离：市场决定价格、币种、库存、配送和时区，locale 决定界面与商品文本；
- 德国市场的默认语言、可选语言和币种以 Joybuy 当时实际公开设置为准；用户切换后所有页面内容自动刷新，不提供逐项翻译按钮；
- 默认复刻链路不强制机器翻译；每个字段必须记录请求语言、实际内容语言、来源哈希和观察时间；
- 数据库时间统一存 UTC，展示时按市场时区转换；
- 第二阶段以 Joybuy 当时站内实际可选的全部国家/地区、语言和货币为准；
- 区域选项作为可抓取、可版本化的配置快照，不写死数量；
- 文本内容按 locale 分表；价格按市场和币种保存实际价目，不用实时汇率替代来源价格。

## 9. 非功能验收

- 视觉宽度：`1440 / 1280 / 390 / 375px`；
- 核心页面整体像素差异不超过 `2%`，关键区域不超过 `1%`；
- 首期性能：常用 API `P95 <= 600ms`，搜索 `P95 <= 1s`，购物端 LCP `<= 5s`；
- 后续优化目标：`300ms / 500ms / 2.5s`；
- 首期负载：200 并发在线用户、50 读 RPS、10 写 RPS；
- 下单并发测试不得出现超卖或重复扣减；
- 支持 Chrome、Edge、Safari 最近两个主要版本及 iOS Safari、Android Chrome；
- 固定 Chromium 作为视觉基准，Firefox 首期只保证功能可用。

## 10. 容量边界

- 50 万 SPU；
- 200 万 SKU/Offer；
- 2,500 万条来源评价；
- 超过该边界前必须重新进行索引、分区、存储和部署评审。
