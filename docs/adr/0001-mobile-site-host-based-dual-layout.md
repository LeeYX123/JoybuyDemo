# 0001 — 手机版采用同应用双布局 + host 判定，m. 站会话独立

购物端需要手机版站点（域名形态 m.localhost:3000，生产为 m. 子域名），且要求视口宽度低于阈值时自动切换。对比了三种方案：纯响应式（无 m. 域名，不满足域名要求）、独立移动应用（工作量近重写，会话/CMS 打通成本高）、同一 Nuxt 应用双布局（一套路由、SSR 按请求 host 判定渲染手机版布局，客户端按宽度阈值双向自动跳转）。选定双布局方案：改动集中、API 与 CMS 数据天然共享，最贴近 joybuy 官方桌面/移动双站做法。

代价与配套决定：后端所有 cookie 均未设 Domain，Chrome 对 localhost 域又拒收带 Domain 属性的 cookie，因此 `localhost` 与 `m.localhost` 的登录态/语言偏好/购物车 cookie 天然隔离。评估过跳转握手自动登录与改 cookie 作用域两条路，前者要新增后端接口与两端握手逻辑，后者在 localhost 下实测大概率走不通。最终接受 m. 站独立登录（同一后端账号体系、数据互通，仅重复登录），手机版默认英文、语言偏好在 m. 站独立记忆。

配套规则：自动切换阈值为 ≤768px，双向触发并保留完整路径；页脚提供「电脑版/手机版」手动切换，手动选择写入 localStorage 永久覆盖自动跳转，直到手动改回；自动跳转须提供测试旁路（如 `?nomobile=1`），避免 e2e 窄视口被重定向干扰。m.joybuy 没有的自有页面（申请店铺、账户中心、帮助/客服、商家落地页等）按 m. 设计语言自行适配，不逐像素但复用手机版壳样式体系。
