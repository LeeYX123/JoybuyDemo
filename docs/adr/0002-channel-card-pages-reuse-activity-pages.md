# 频道卡的落地页复用活动页，而不是另建一套页面模型

品类页 `.channel-cards` 的 31 个活动链接要落到本地可打开、可配置的页面。我们让这些页面复用已有的活动页（`/active/<id>`，ID 与真站一致），只给频道卡加一个指向活动页的绑定字段；楼层商品采用「先爬真站拿结构与白名单，再用本地库快照选品，缺量再爬」的方式一次性写死，服务端按「店铺页优先、每频道最多 3 张、母婴童玩除外」截断卡片。

## 考虑过的替代方案

- **另建一套「品类活动页」模型**：结构几乎与活动页相同，但会分裂后台入口、渲染组件和采集链路。放弃。
- **卡片直接填站内 URL**：改动最小，但后台无法校验页面是否存在，运营填错只能等用户点开才发现。放弃。
- **楼层按规则实时选品**：库内上新自动补位，但请求代价高、后台难以预览，且「这层到底会变什么」对运营不可预期。选择快照，并配一条重跑命令。
