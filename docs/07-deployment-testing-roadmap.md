# 部署、测试与路线图

## 1. 本地开发

Windows 本地采用混合模式：

- Docker Desktop/WSL2：MySQL、Redis、邮件测试服务等基础设施；
- Windows 本机：Django、Nuxt、Vue、Celery，获得快速热更新；
- Playwright 浏览器与 Scrapy 可按任务在本机或容器运行；
- `var/` 保存本地媒体、原始响应和开发数据；
- 提供一键完整容器环境，在上线前验证 Linux 一致性。

不得把本地路径、盘符或开发密钥写入业务数据。

## 2. 首个生产部署

目标：单台 Ubuntu 服务器 + Docker Compose。

```text
Internet
  -> Nginx (HTTPS, routing, /media)
     -> Nuxt storefront
     -> Admin SPA static files
     -> Django API
        -> MySQL
        -> Redis
        -> Celery workers
        -> Scrapy workers
        -> Playwright workers
     -> /srv/joybuy/data/media
```

建议容器：

- `nginx`
- `storefront`
- `admin-web`
- `api`
- `celery-default`
- `celery-crawl`
- `celery-browser`
- `celery-media`
- `celery-beat`
- `mysql`
- `redis`
- `prometheus`
- `grafana`
- 日志采集组件

数据库和媒体必须挂载宿主机持久卷；备份不能只存在同一块磁盘。

## 3. 安全基线

- HTTPS，HTTP 自动跳转；
- Secure、HttpOnly、SameSite Cookie；
- CSRF、CORS 白名单和安全响应头；
- 平台管理员 TOTP；
- 密码使用 Django 推荐的强哈希器；
- 登录、验证码、搜索和写接口限流；
- 上传文件类型/大小/内容校验；
- 数据库、Redis 不暴露公网；
- 秘密通过环境或秘密文件注入；
- 依赖和容器镜像漏洞扫描；
- 后台高风险操作二次确认；
- 审计日志记录变更前后值和原因。

## 4. 备份与恢复

- MySQL 每日全量备份；
- 持续保留 binlog，目标 `RPO <= 15 分钟`；
- 媒体目录每日增量快照；
- CMS、配置和加密密钥按独立策略备份；
- 目标 `RTO <= 4 小时`；
- 定期在隔离环境恢复数据库与媒体；
- 未通过恢复演练的备份不能视为有效备份。

## 5. 监控

必须监控：

- HTTP 状态、吞吐、P50/P95/P99；
- Django 异常和慢查询；
- MySQL 连接、锁、复制/备份、磁盘；
- Redis 内存和 key 淘汰；
- Celery 队列长度、失败、重试和延迟；
- Scrapy 成功率、状态码、字段缺失率；
- Playwright 会话和风控暂停；
- 媒体下载/转码失败；
- 磁盘容量和 inode；
- 订单超时任务和库存释放一致性。

不建设商品曝光/点击等经营分析，但技术监控和审计必须保留。

## 6. 自动化测试

### 6.1 后端

- 模型约束和权限；
- API 契约；
- 买家/员工会话隔离；
- 购物车合并；
- 创建订单事务；
- 并发库存预占和超时释放；
- 支付地区不支持；
- 来源层与覆盖层；
- 爬虫导入幂等；
- 备份迁移兼容性。

### 6.2 爬虫

- 保存的 HTML/JSON fixture 解析；
- 页面结构版本；
- 字段质量阈值；
- 类目包含子类目；
- 限量、排序和随机 seed；
- 增量和完整刷新；
- 评价分层采样；
- 媒体哈希去重；
- 账号暂停、全局熔断和任务不可接管。

### 6.3 前端

- 组件状态；
- 响应式布局；
- 表单可访问性；
- 购物车、结算、订单主链路；
- API 错误态；
- 多语言伸缩；
- 本地资产与无 CDN 检查。

### 6.4 端到端

核心脚本：

1. 游客浏览和搜索；
2. 查看 SPU/SKU 与评价媒体；
3. 加入匿名购物车；
4. 注册/登录并合并购物车；
5. 地址、配送、运费和订单确认；
6. 创建待支付订单；
7. 点击支付得到地区不支持提示；
8. 60 分钟超时模拟后订单取消、库存恢复；
9. 平台查看商品、爬虫任务和订单。

## 7. 视觉验收

- 固定视口：1440、1280、390、375；
- 固定 Chromium、字体、locale、时区和测试数据；
- 动态区域冻结；
- 整页差异 `<= 2%`；
- 关键区域 `<= 1%`；
- 自动热力图 + 人工复核；
- 桌面端和手机端均为发布门槛。

## 8. 性能与容量测试

首期门槛：

- 常用 API `P95 <= 600ms`；
- 搜索 `P95 <= 1s`；
- 购物端 LCP `<= 5s`；
- 200 并发在线用户；
- 50 读 RPS、10 写 RPS；
- 下单压测不超卖、不重复预占、不重复释放。

优化目标：API 300ms、搜索 500ms、LCP 2.5s。

容量验证至少覆盖：50 万 SPU、200 万 SKU/Offer、2,500 万评价的索引和查询设计。可以使用生成数据做容量测试，但不得冒充来源业务数据。

## 9. 发布门槛

以下任一失败不得上线：

- 核心单元/API/E2E 测试；
- 订单库存一致性；
- 数据迁移和回滚演练；
- 备份恢复演练；
- 核心视觉阈值；
- 严重或高危安全问题；
- 爬虫质量闸门；
- 生产容器健康检查；
- 本地/CDN 外链扫描发现未批准外链。

## 10. 实施路线图

本节描述阶段目标；实际编码必须按 [按 Codex 会话拆分的实施工作包](./08-implementation-work-packages.md) 一次执行一个工作包。

### 阶段 0：基线与工程准备

- 获取授权测试账号并手动建立 Joybuy 会话；
- 保存网站快照、页面清单和资产清单；
- 锁定依赖版本、代码规范和环境模板；
- 建立 CI、测试框架、Docker 和监控基座。

### 阶段 1：爬虫试点与数据基座

- 来源/本地分层模型；
- 类目任务管理；
- Scrapy + Playwright；
- 商品、SKU、Offer、媒体和评价；
- 3-5 个类目、每类 50-100 商品；
- 质量闸门、重放和增量更新。

### 阶段 2：购物端核心

- 首页、类目、搜索、商品、评价；
- 邮箱/手机号登录；
- 收藏和购物车；
- 地址、配送、结算；
- 待支付订单和地区不支持提示；
- 响应式与视觉回归。

### 阶段 3：平台管理端

- 目录、商品、覆盖值、媒体、评价；
- CMS；
- 买家、员工、商家基础管理；
- 爬虫账号和任务；
- 待支付/取消订单；
- 审计、配置和通知模板。

### 阶段 4：全站数据与上线

- 扩大类目和全站增量；
- 容量、性能、安全、恢复和视觉验收；
- Ubuntu Docker Compose 上线；
- 建立监控、告警、备份和运行手册。

### 第二阶段

- Joybuy 当时可选的全部市场、语言和货币；
- Facebook、Google 登录；
- 复杂优惠、JoyPlus、积分等按需要启用；
- 真实支付另行设计后才能启用成功支付订单。

### 待用户提供参考后

- 商家端页面与具体功能；
- 商家订单、履约、物流和售后；
- 商家经营分析。

### 远期可选

- Apple 登录；
- 第三方客服；
- 真实支付、退款、礼品卡和 Repeat & Save 自动扣款；
- 多机部署、对象存储和独立搜索引擎（仅在指标证明需要时）。
