商家端开发文档

版本 V1.3 · 2026-11-05 · 状态：开发交付基线（不是后端已实现说明）

阅读说明

以最新确认需求为准，本文按当前独立模块说明页面、每项功能、数据/表单字段、流程、校验及验收。字段表包含页面字段及该功能必需的关联数据，并不表示每个字段都在当前页面可编辑。原型与正式服务差异见共用字段与接口约定。接口名和数据表均为建议设计，尚未实现。

原型文件：海外电商商家后台.html；源码位置：work/merchant/build-current.cjs。不修改原型，仅整理文档。

商家端目前没有完整的商家登录、入驻表单或账号注册模块；正式开发需由统一登录服务提供商家身份及所属店铺。页面里的示例身份和后台预览hash不能用于生产授权。

全局交互约定

  • 页面列表的查询、重置、分页、空状态、错误状态要明确；修改筛选重置到第一页。商品相关页码居中，不显示件数说明。
  • 确认发货、上架、下架、解封、完成全部节点、资金入账等使用二次确认或明确的确认提交。加载时禁用重复提交，服务端仍要幂等。
  • 不增加多余宣传小字、店铺经营正常横幅、处罚/修改说明必填框。保留必要的字段标签、错误提示、业务状态和真实资金信息。
  • 图片保存失败不能留下仅修改了价格或记录的半成功状态。正式上传到文件服务，返回对象ID和URL。
  • 金额用CNY两位小数示例；订单成交金额和发货成本必须使用不同标签。
  • 数据归属、资金事务、会话授权和图片访问权都由服务端验证。

M01 经营看板

查看当前店铺经营数据，不承载管理后台配置。

功能清单与交互

功能入口/触发处理与结果校验和边界
数据卡片进入页面今日订单、待发货、今日曝光、总关注及高亮增量、店铺状态、信誉分所有数字按本店授权范围统计
图表切换各图近一周/近一月订单柱状图、曝光柱状图、按订单数量的品类占比饼图切换只影响对应图，空数据不除零
关注记录点击关注变动记录查看后台新增关注的日期与增量总量保留，次日0点清增量
平台经营通知点击通知进入对应通知详情/处理入口不增加店铺正常、待处理订单数量等顶部提示横幅

业务规则

  • 店铺首页名称固定为经营看板。
  • 不显示钱包余额或今日新增关注卡；总关注右侧可显示+30等当天增量。
  • 图表数值和日期目前有演示常量，正式必须接统计接口。

流程

  1. 登录商家身份
  2. 获取本店统计
  3. 显示数据卡
  4. 切换图表窗口
  5. 打开通知

验收要点

  • M01-01：通过“进入页面”执行“数据卡片”，应满足：今日订单、待发货、今日曝光、总关注及高亮增量、店铺状态、信誉分；所有数字按本店授权范围统计。
  • M01-02：通过“各图近一周/近一月”执行“图表切换”，应满足：订单柱状图、曝光柱状图、按订单数量的品类占比饼图；切换只影响对应图，空数据不除零。
  • M01-03：通过“点击关注变动记录”执行“关注记录”，应满足：查看后台新增关注的日期与增量；总量保留，次日0点清增量。
  • M01-04：通过“点击通知”执行“平台经营通知”，应满足：进入对应通知详情/处理入口；不增加店铺正常、待处理订单数量等顶部提示横幅。

原型实现定位

work/merchant/upgrade.js、followers-profit.js、operations-complete.js、admission-policy.js。同名函数可能被后加载脚本覆盖，应结合构建顺序查阅，不能只阅读旧app.js或index-v1.html。

查看自己的已上架商品并编辑店铺资料。

  • 保证金未满足初始开店条件时禁止上架。

流程

  2. 筛选已上架商品

  4. 编辑名称头像

M03 商品上架中心

从平台商品池选择商品上架至当前店铺。

功能清单与交互

功能入口/触发处理与结果校验和边界
品类筛选点击直接展示的品类按钮按品类筛选平台商品不使用品类下拉框；包含活动商品
商品搜索与分页输入商品名称/点击页码搜索后重置到第1页，居中分页无匹配显示空状态
查看详情商品卡/详情按钮展示ID、品类、描述、成本和零售价不将成本和成交金额混淆
上架二次确认点击上架商品弹出商品信息和确认上架按钮已上架不可重复，上架需经营许可
确认上架确认弹窗创建店铺商品关系并在店铺管理出现后端唯一约束防重复

业务规则

  • 品类为家居生活、电子产品、美妆个人护理、小家电、健康与保健、计算机与配件、服装与配饰、户外运动、宠物用品、婴幼儿用品、游戏及配件、活动商品。
  • 成本与零售价在卡片分列。
  • 可售条件同时校验平台商品状态及店铺状态，不能仅禁用前端按钮。

流程

  1. 选择品类
  2. 搜索商品
  3. 查看详情
  4. 点击上架
  5. 二次确认
  6. 校验店铺资格
  7. 创建上架关系

跨端联动与端到端流程

入驻、保证金与开店

  1. 用户提交入驻申请
  2. 后台审核：是否需保证金、金额、未处理封店天数
  3. 免缴：直接接单中；需缴：待缴保证金
  4. 客服在保证金管理充值
  5. 首次缴足：接单中并允许上架
  6. 审核后的保证金选择永久锁定

发货、确认收货与订单回款

  1. 订单待处理，保存成本/单价/支付方式快照
  2. 商家确认发货：校验钱包≥成本合计
  3. 原子扣成本、生成订单发货流水，状态已发货
  4. 后台/物流按8节点推进并记录时间
  5. 用户确认收货：状态已完成
  6. 钱包增加订单成交金额，生成一次订单回款
  7. 商家详情隐藏整个进度区，收益标签为盈利

提现审核和出款

  1. 商家填写银行卡或数字货币链上收款信息
  2. 金额不超过钱包可用余额
  3. 验证6位钱包密码，创建待审核并占用余额
  4. 后台审核：通过或打回（打回退回一次）
  5. 审核通过：记录凭证，开始转账
  6. 到账：结束；失败：退回一次
  7. 商家统一资金明细显示全过程

推荐返佣核算与人工到账

  1. 商家复制推荐码分享
  2. 新人入驻绑定推荐关系
  3. 按每位新人当月发货成功金额统计
  4. 每月1日冻结上月返佣快照，状态待发放
  5. 客服7个工作日内确认返佣
  6. 原子加推荐商家钱包，生成推荐返佣流水
  7. 商家活动和钱包均显示已到账；重复确认无效

商品好评推送和多轮回复

  1. 后台输入店铺ID搜索
  2. 按名称/商品ID搜索本店已上架商品
  3. 填写通知标题、评论，图片可选
  4. 推送后商家未读通知
  5. 商家查看商品、文字、图片、最后一行时间
  6. 商家回复，后台同一记录继续回复
  7. 平台新回复使商家重新未读

白名单余额购买

  1. 用户已注册商城账号
  2. 后台搜索账号并加入白名单
  3. 后台向白名单账号充值
  4. 商城校验启用状态和地区/白名单
  5. 服务端获取订单真实应付金额
  6. 余额足够时一次扣款并写消费记录
  7. 移出白名单取消专属权限，余额和历史保留

超时自动封店与客服解封

  1. 订单仍待处理且商家已具备经营资格
  2. 按商家未处理整数天数检查超时
  3. 自动封店并生成原因、日志、通知
  4. 商家联系客服
  5. 客服在商家管理二次确认解封
  6. 恢复接单，重置未处理订单履约起算时间
  7. 不扣钱包或保证金，不存在解封审核中

正式开发补齐项

  1. 商家身份登录和服务端店铺归属。
  2. 看板真实统计、商品图片规格统一读取、平台活动/普通通知/客服/提现等两端数据贯通。
  3. 服务端发货扣成本、确认收货回款和提现占用/退回事务，禁止本地余额作为事实源。
  4. 商家操作在线时间由服务端记录，跨日关注增量和返佣任务由后端运行。
